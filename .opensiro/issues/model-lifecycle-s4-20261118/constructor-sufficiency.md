## Proposed source-native C witness

Scenario HYPOTHETICAL: a future dated vendor sunset notice predicts reduced availability before failure. Developer opts into a bounded advisory provider+model allowlist. Advisor assesses competing future choices and publishes a typed, expiring proposal to existing host/S3. S3 applies only an already-authorized next-turn configuration or rejects it, returning an attributed response. Later operational/model outcome flows back to advisor to revise its subsequent choice. User/host S5 rights and current-running-step model remain untouched. This complete path is **PROPOSED_C_SUFFICIENT IF IMPLEMENTED AND VALIDATED**, not evidence of a current C.

## P0 / P1 / P2 and native acceptance

P0: smallest optional independent future S4 actor with lawful next-turn host proposal/ack and observed later run return. P1: provider notice provenance, expiry, authorization, blocked unaffordable/unavailable model, duplicate prevention, denial feedback and native tests. P2: optional measured cost/quality comparisons.

Positive: independently select from at least two valid future options on a dated vendor notice; S3 approves, next turn actually changes within approved configuration, later result returns and changes future strategy. Negative: stale/unsigned notice, unauthorized provider/model/cost, no permission, same-running-turn change, denied proposal, duplicate and missing effect/feedback must NOT be passed as C. Contrast with native catalog + picker; compare actual original-native regression results before implementation conclusions.

**Stop/falsify:** equivalent shipped first-party prospective S4 ownership/effect/return; no lawful host/S3 new port; pure user-only prompt or alert; or impossible feedback. Absence of measured product adoption value does not prove architectural impossibility. Native tests NOT_RUN, cost NOT_MEASURED; original [docs/contributing.md](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/docs/contributing.md) forbids external code PRs. No external/public fork Issue or PR was published.


## v0.18.1 native-specific clarification (2026-11-20; nonbinding)

**Operator-visible future capability if built:** in an explicitly enabled Codex app-server/TUI deployment, a developer can receive an *auditable, pre-retirement model-migration proposal* grounded in an attributable future provider notice, approve or deny the proposed next-turn target under existing provider/model/cost policy, and later see whether the selected model actually took effect and how the next run ended. No silent default switch and no change to the currently executing step. This is a **hypothetical proposal**, not an observed user need or product mandate.

**Reuse actual Codex components rather than a generic VSM controller:**

1. [`ModelsManager` and `model_catalog_updates()`](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/models-manager/src/manager.rs) expose a `watch::Receiver<Option<Arc<RefreshedModelCatalog>>>` and provider-scoped catalog refresh/cache. [App-server `ModelCatalog::list_models(RefreshStrategy::Online)`](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/app-server/src/model_catalog.rs) is already called by [`ModelsRefreshWorker::spawn_with_interval`](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/app-server/src/models_refresh_worker.rs) every 4m30s. This is the **existing state/refresh signal**; do not introduce a second scheduler or claim that a catalog delta itself proves a dated future sunset.
2. **Minimal new S4 input/actor:** only when configured, a narrow provider-specific dated future-notice adapter must establish provenance/expiry (not shipped), combine it with the effective model catalog, and select **retain / propose allowed successor / hold** autonomously with a reason and bounded authority. Absent a trustworthy future notice, remain in hold/observe. This optional actor is new; no claim that `ModelsManager` already contains it.
3. **Minimal new handoff, not a duplicate model controller:** add one typed, correlated proposal/decision acknowledgement to Codex's existing app-server/host configuration path, with `approved`, `denied`, or `deferred` outcome and the original developer/user authority intact. Preserve the [existing user-operated `ModelMigrationOutcome` selection](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/tui/src/model_migration.rs) and [startup migration acknowledgement](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/tui/src/app/startup_prompts.rs); neither is automatic S4 authorization. Reuse [`Session::update_settings_if` and `thread_settings::emit_applied`](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/core/src/session/model_catalog_settings.rs) for the **next-turn** effect and application receipt, not current-step mutation. Proposed typed message/actor names remain design placeholders, not shipped APIs.
4. **Missing S3→S4 return:** correlate the proposal ID with a *later* effective provider/model setting and subsequent turn outcome, including denied, absent, stale or failed application. `emit_applied` is **settings evidence only**, not a later-run success signal. Feed both into the future-options choice; otherwise this remains a one-way warning and fails the claimed S4=C closure.

**Smallest new native edit set to test:** (A) optional future-notice adapter/decision function at the model catalog boundary; (B) single policy-checked proposal/ack seam at app-server → session settings, preserving user migration choice; (C) correlated next-turn applied + run-result feedback to the same optional advisor. Reuse catalog refresh, TUI model picker, existing next-turn persistence and host rights unchanged. **No generic scheduler, supervisor, second policy authority, new metric or automatic model switch.**

**Source-specific acceptance before any C claim:** with a deterministic dated notice and two eligible Codex model choices, the advisor must distinguish retain/propose/hold; a checked human/host decision must change only a later turn; a separate later result must return to advisor. Negative controls: provider mismatch, stale/unsigned notice, disallowed/costlier successor, user rejection, repeated proposal, absent applied event, failed next turn and a live step whose model must remain unchanged. Run the native `models_refresh_worker_tests.rs`, TUI migration tests and session setting/turn tests in a future implementation; **NOT_RUN** in this plan. **Falsify** if a complete equivalent native future-decision/handoff/return already ships, no lawful host seam exists, or the future notice cannot be verified. The v0.18.0 proposal GO is unchanged; v0.18.1 adds **specificity only**, not a GO gate.
